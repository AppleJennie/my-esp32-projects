# 鼾声分析与睡眠健康守护 — 答辩核心材料

---

## 一、为什么要做这件事？（痛点引入）

> 很多人打鼾自己不知道，但鼾声背后可能藏着健康风险。

- **阻塞性睡眠呼吸暂停（OSA）**：鼾声不规律、伴随呼吸暂停是典型标志
- **夜间低血氧**：呼吸暂停时血氧下降，长期影响心血管健康
- **传统监测门槛高**：多导睡眠仪（PSG）需要去医院、贴满身电极，成本高、不便捷
- **智能手环测不到**：手环靠加速度计，能测体动但测不到鼾声和呼吸

**我们的定位**：做一台放在床头的**AI 睡眠健康守护设备**，无创、无感、低成本，在家就能做睡眠健康初筛。

## 二、核心功能一：鼾声分析

### 2.1 不是录音，是端侧 AI 实时推理

**普通做法**：麦克风录音上传到云端分析。

**我们的做法**：原始音频在 ESP32 本地处理，只输出"有没有鼾声"，录音不上传。

**技术流程**：

```
麦克风采集
    ↓
音频分帧（每 100ms 一帧）
    ↓
MFCC 特征提取（49 帧 × 13 维梅尔频率倒谱系数）
    ↓
TFLM 量化神经网络推理（每 3 秒一次，滑动窗口 50% 重叠）
    ↓
输出鼾声概率（0~1 浮点数）
    ↓
后处理：连续 2 帧 > 0.6 → 判定鼾声开始
        连续 3 帧 < 0.6 → 判定鼾声结束
```

**关键参数**：
| 指标 | 数值 |
|------|------|
| 推理周期 | 每 3 秒 |
| 窗口长度 | 49 帧（约 3 秒音频） |
| 特征维度 | 13 维 MFCC |
| 判定阈值 | 概率 > 0.6 |
| 内存策略 | 张量空间分配在 PSRAM |

### 2.2 输出什么？

| 数据项 | 说明 |
|--------|------|
| 鼾声次数 | 整晚发生多少次鼾声事件 |
| 鼾声总时长 | 累计打鼾多少分钟 |
| 鼾声指数 | 每小时打鼾次数（次/h） |
| 最大呼声强度 | 最大分贝值 |
| 鼾声等级 | 无 / 轻度（<5次/h）/ 中度（5~10次/h）/ 重度（>10次/h） |

## 三、核心功能二：睡眠健康守护

### 3.1 不只是鼾声，是多维度生命体征融合

单一数据源不可靠，我们融合三类数据：

| 数据源 | 监测指标 | 健康意义 |
|--------|---------|---------|
| **音频** | 鼾声概率、环境噪声 | OSA 初筛、睡眠环境评估 |
| **雷达** | 心率、呼吸率、体动、人体存在 | 生命体征实时监测、翻身次数统计 |
| **环境** | 温度、湿度、光照 | 睡眠环境舒适度评估 |

### 3.2 睡眠质量评分算法（0~100 分）

不是拍脑袋，是多维度量化扣分：

```
基础分：100 分

SpO2 扣分：
  - SpO2 < 90%：扣 15 分（"血氧饱和度偏低"）
  - SpO2 < 95%：扣 5 分（"血氧轻微不足"）

心率扣分：
  - 夜间心率 >100 或 <50：扣 10 分（"夜间心率异常"）

呼吸扣分：
  - 呼吸幅度偏浅：扣 10 分
  - 呼吸节律不稳定：扣 10 分

体动扣分：
  - 夜间体动 >20 次：扣 10 分（"较多体动"）
  - 夜间体动 >10 次：扣 5 分（"少量体动"）

鼾声扣分：
  - 检测到鼾声：扣 10 分（"疑似鼾声"）

环境扣分：
  - 环境噪声大：扣 5 分（"睡眠环境较嘈杂"）
```

**风险等级**：
| 分数 | 等级 | 说明 |
|------|------|------|
| ≥80 | 低风险 | 睡眠质量良好 |
| 60~79 | 中风险 | 存在需要注意的问题 |
| <60 | 高风险 | 建议关注或就医 |

### 3.3 呼吸暂停风险监测

**判断逻辑**：
- 血氧 < 90% 且持续 → 疑似低血氧事件
- 呼吸率 < 10 次/分 → 疑似呼吸抑制
- 血氧下降 + 鼾声中断 → 高度疑似呼吸暂停

**风险等级**：
| 条件 | 等级 |
|------|------|
| 无症状 | 低 |
| 疑似事件 ≥2 次 或 血氧低于 90 | 中 |
| 疑似事件 ≥5 次 或 最低血氧 < 88 | 高 |

### 3.4 智能改善建议（AI 建议页）

不是泛泛而谈，是基于数据的**个性化建议**：

| 检测到的问题 | 给出的建议 |
|-------------|-----------|
| 检测到鼾声 | 建议尝试侧卧睡眠、关注枕头高度 |
| 夜间体动多 | 建议睡前放松、减少夜间翻身 |
| SpO2 < 95% | 建议保持卧室通风 |
| 环境嘈杂 | 建议降低睡眠环境噪音 |
| 温度不合适 | 建议适当保暖或通风 |

## 五、隐私设计（加分项）

| 设计 | 说明 |
|------|------|
| **原始音频不出设备** | MFCC 特征提取 + 神经网络推理在本地完成，只有"鼾声概率"上传 |
| **录音不上云** | 不存储、不传输原始音频波形 |
| **SD 卡本地存储** | 传感器数据存在本地 TF 卡，用户拥有数据主权 |
| **无摄像头** | 夜间场景不涉及视频采集，彻底避免隐私顾虑 |

## 七、评委可能追问

| 追问 | 回答 |
|------|------|
| "准确率怎么验证？" | 目前用阈值后处理做事件判定，后续计划用 SD 卡积累的数据与多导睡眠仪做对比标定 |
| "能替代医院的睡眠监测吗？" | **不能替代，是初筛工具**。我们的定位是家庭健康观察，发现异常后提醒用户去医院做专业检查 |
| "为什么只做鼾声不做其他呼吸音？" | 鼾声是 OSA 最典型的家庭可检测标志，且特征明显（低频能量集中），适合端侧模型。后续可扩展咳嗽、哮鸣音等 |
| "雷达怎么监测心率和呼吸？" | 毫米波雷达通过检测胸腔微动来提取心跳和呼吸信号，非接触、无感 |
| "评分算法的医学依据是什么？" | 参考了 PSQI 睡眠质量指数和 AASM 睡眠呼吸暂停判读规则中的关键指标阈值，做了工程化简化 |
| "有没有考虑过误报？" | 有。通过滑动窗口和连续帧判定减少瞬时噪声误报；同时所有高风险建议都带免责声明，不替代医学诊断 |

## 八、演示建议

1. **说"晚安"** → 设备启动监测（屏幕显示"监护中"）
2. **模拟鼾声或展示波形页** → 屏幕实时显示呼声分贝变化
3. **等待几秒后说"我起床了"** → 设备停止监测
4. **说"查报告"或"生成睡眠报告"** → 大模型语音播报：
   - "昨晚睡眠评分 82 分，轻度风险。检测到 18 次鼾声事件，疑似呼吸暂停 2 次，最低血氧 91%。建议尝试侧卧睡眠，保持卧室通风。"
5. **（如有条件）展示触摸屏的报告页或 Web 页** → 显示结构化数据
