# 小智 AI 睡眠监测伴侣

> 基于 ESP32 的 AI 语音交互终端，集成本地鼾声检测、多传感器睡眠监测与大模型语音对话能力。

## 项目简介

本项目是一款面向家庭健康场景的嵌入式 AI 设备。以 ESP32-S3 为核心，通过 **离线语音唤醒** 与大模型云端服务进行自然语言交互，同时内置 **本地 AI 睡眠监测引擎**，可在夜间无感监测用户睡眠状态，提供鼾声检测、心率呼吸追踪、睡眠质量评分与健康建议。

**本项目不使用摄像头模块**，所有感知能力来源于音频与低功耗外接传感器，兼顾隐私保护与监测精度。

## 核心功能

### 1. AI 语音交互
- **离线语音唤醒**：基于 ESP-SR / AFE 音频前端引擎，本地识别唤醒词
- **流式语音对话**：麦克风音频经 OPUS 编码后通过 WebSocket / MQTT 实时上传云端
- **大模型能力**：接入云端 LLM（Qwen / DeepSeek 等），支持流式 ASR + LLM + TTS 全链路语音交互
- **对话打断（AEC）**：支持设备端回声消除，实现边说边听的实时对话体验
- **多语言支持**：中文、英文、日文等（通过 Kconfig 配置切换）

### 2. 本地 AI 睡眠监测（核心亮点）

#### 2.1 本地鼾声检测（TensorFlow Lite Micro）
- **模型部署**：在 ESP32 上运行 TFLM 量化神经网络模型
- **特征提取**：MFCC（梅尔频率倒谱系数）音频特征，49帧 × 13维
- **推理方式**：每 3 秒进行一次滑动窗口推理（50% 重叠），输出鼾声概率
- **事件检测**：连续 2 帧概率 > 0.6 判定为一次鼾声事件开始，连续 3 帧 < 0.6 判定结束
- **内存优化**：张量运算空间分配在 PSRAM，避免内部 DRAM 溢出

#### 2.2 多传感器数据融合（SleepDataCenter）
通过 UART1（GPIO16/17，115200bps）接收外接传感器节点数据，实现多维度睡眠监测：

| 数据源 | 内容 | 用途 |
|--------|------|------|
| 本地麦克风 | 音频 RMS、VAD、鼾声概率 | 鼾声检测、环境噪声评估 |
| 雷达传感器 | 人体存在、体动等级、心率、呼吸率 | 生命体征监测、体动统计 |
| 环境传感器 | 温度、湿度、光照强度 | 睡眠环境评估 |

#### 2.3 睡眠质量评分算法
基于多源数据综合计算睡眠评分（0~100分）：
- **血氧**：SpO2 < 90% 扣 15 分，< 95% 扣 5 分
- **心率**：夜间心率 > 100 或 < 50 扣 10 分
- **呼吸**：呼吸幅度偏浅 / 节律不稳定各扣 10 分
- **体动**：夜间体动过多扣 5~10 分
- **鼾声**：检测到鼾声扣 10 分
- **环境噪声**：环境嘈杂扣 5 分

输出风险等级（低/中/高）与个性化改善建议。

#### 2.4 语音指令控制
用户可通过语音直接控制睡眠监测：
- "开始睡眠监测" / "晚安" → 启动监测会话
- "停止监测" / "起床" → 结束监测并保存数据
- "生成睡眠报告" / "查报告" → 调用 MCP 工具向云端请求报告

#### 2.5 数据持久化
- **SD 卡日志**：原始传感器 JSON 数据实时写入 SD 卡，便于后期分析
- **NVS 存储**：设备设置、校准参数断电保存

### 3. MCP 设备控制协议
设备端作为 MCP Server，通过 JSON-RPC 2.0 向云端暴露可控工具：

| 工具名 | 功能 |
|--------|------|
| `self.get_device_status` | 获取设备实时状态（音量、电量、网络等） |
| `self.audio_speaker.set_volume` | 设置扬声器音量（0~100） |
| `self.screen.set_brightness` | 设置屏幕亮度（0~100） |
| `self.screen.set_theme` | 切换屏幕主题（light/dark） |
| `self.AEC.set_mode` | 切换 AEC 对话打断模式 |
| `self.AEC.get_mode` | 获取当前 AEC 状态 |
| `self.sleep.get_status` | 获取睡眠监测实时状态 |
| `self.sleep.get_vitals` | 获取心率/呼吸率/血氧数据 |
| `self.sleep.get_snore_status` | 获取鼾声统计 |
| `self.sleep.get_environment` | 获取环境温湿度/光照 |
| `self.sleep.generate_report` | 生成完整睡眠报告 |
| `self.get_system_info` | 获取系统信息（User Only） |
| `self.reboot` | 重启设备（User Only） |
| `self.upgrade_firmware` | OTA 固件升级（User Only） |

### 4. 显示与交互
- **LCD / OLED 显示屏**：显示对话内容、情绪表情、系统状态
- **LED 状态指示**：通过 LED 颜色/闪烁反馈设备状态（唤醒/聆听/说话/离线）
- **实体按键**：支持单击/长按触发对话、配网等功能

## 软件模块说明

| 目录/文件 | 说明 |
|-----------|------|
| `main/application.cc` | 主程序事件循环，管理设备状态机、网络事件、MCP 消息分发 |
| `main/audio/` | 音频编解码、OPUS 编解码、音频前端处理（AFE）、唤醒词检测 |
| `main/protocols/` | WebSocket / MQTT 协议实现，音频通道管理 |
| `main/mcp_server.cc` | MCP Server 核心，工具注册与 JSON-RPC 处理 |
| `main/sleep_monitor/` | 睡眠监测引擎：麦克风驱动、MFCC 特征提取、TFLM 模型推理 |
| `main/sleep_data_center/` | 多源数据融合中心、传感器 UART 接收、睡眠评分、SD 卡日志 |

| `main/boards/` | 各开发板硬件抽象层（Board HAL） |

## 设备状态机

```
Starting ──► Activating ──► Idle ◄──────┐
                              │         │
                              ▼         │
                         Connecting     │
                              │         │
                              ▼         │
                          Listening ────┤ (说完自动/手动返回)
                              │         │
                              ▼         │
                          Speaking ─────┘
```

- **Idle**：待机状态，监听唤醒词
- **Listening**：聆听用户说话，音频流上传云端
- **Speaking**：播放云端返回的 TTS 语音
- **Sleep Monitoring**：在 Idle 状态下后台并行运行，不干扰语音交互

## 通信协议

### 音频传输
- 编码：OPUS（16kHz 采样率，60ms 帧长，单声道）
- 传输：WebSocket 或 MQTT+UDP 混合协议
- 下行音频：云端 TTS 输出 OPUS 流，设备端实时解码播放

### MCP 协议
- 基于 JSON-RPC 2.0 的设备能力发现与调用
- 设备作为 MCP Server，云端作为 MCP Client
- 支持 `initialize`、`tools/list`、`tools/call` 标准方法
- 支持工具分页（单包 ≤ 8KB）与 AI/用户工具隔离

### 传感器 UART 协议
外接传感器节点通过 UART1 以 JSON 行格式上报数据：

```json
{"radar":{"exist":1,"motion":0,"hr":72,"br":16,"dist":120}}
{"temp":24.5,"humi":55.0,"light_raw":32}
{"audio_db":-45.2,"vad":0}
```

## 开发环境

- **框架**：ESP-IDF v5.4+
- **芯片**：ESP32-S3（推荐）/ ESP32-P4 / ESP32-C3
- **开发工具**：VSCode + ESP-IDF 插件 或 Cursor
- **编译**：支持 menuconfig 选择开发板类型、网络类型（Wi-Fi / 4G）、语言等

## 快速开始

1. 安装 ESP-IDF v5.4 并设置环境变量
2. 使用 `idf.py menuconfig` 选择开发板型号与网络配置
3. 编译并烧录：`idf.py build flash monitor`
4. 设备首次启动后通过按键进入 Wi-Fi 配网模式，连接手机热点或路由器
5. 配网成功后自动激活，接入云端服务即可语音对话

## 项目特色与技术创新

1. **端侧 AI 推理**：在 ESP32 资源受限环境下成功部署 TFLM 神经网络，实现本地实时鼾声检测，无需云端依赖即可保障隐私
2. **多模态感知融合**：音频 + 雷达 + 环境传感器数据在设备端融合，不依赖单一数据源，提升监测可靠性
3. **语音即交互**：用户全程通过自然语言与设备交互，无需 App 或触屏操作，适合夜间无感使用场景
4. **事件驱动架构**：主循环基于 FreeRTOS EventGroup，网络、音频、UI、传感器各模块解耦，系统响应稳定
5. **MCP 标准化协议**：设备能力通过 MCP 协议自动暴露给大模型，AI 可直接调用设备功能，扩展性强
